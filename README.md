# 코스피 종목 분석

코스피 **전 종목(942개)** 을 시가총액 · 부채비율 · 영업이익률 · PER · ROE · 배당수익률 · 매출성장률로
조건 검색하고, **원하는 종목을 직접 골라** 종가 분석·보고서·엑셀까지 받는 무료 주식 분석 도구입니다.

- **데이터 출처**: 네이버금융 공개 API (`m.stock.naver.com`, `api.finance.naver.com`)
- **기술 스택**: Hono + TypeScript + Vite → Cloudflare Pages (Workers)
- **프론트엔드**: 바닐라 JS (프레임워크 없음), CDN 미사용 · 자체 CSS
- **만든 사람**: 최미경 (기획 · 디자인 · 개발)
- **현재 버전**: **v1.0.0** (2026-10-24 릴리스)

## 0. 버전 정책

지금까지 완성된 기능을 **v1.0.0으로 동결**하고, 이후 추가되는 자료는 **v1.1.0**부터 쌓습니다.

| 규칙 | 의미 | 예시 |
|---|---|---|
| `v1.0.x` | 기존 기능의 **버그 수정**만 | 표 오탈자, 색상 오류 |
| `v1.1.0` | **기능 추가** | 새 지표, 새 다운로드 형식, 새 화면 |
| `v2.0.0` | 기존 동작이 **깨지는** 구조 변경 | API 응답 형식 변경 |

**버전을 확인하는 3가지 방법**

1. **화면 푸터** — 우측 하단 `v1.0.0` 배지
2. **헬스체크 API** — `GET /api/health` → `{"ok":true,"version":"1.0.0",...}`
3. **소스** — `src/version.ts` 의 `APP_VERSION`

**단일 출처 원칙**: 버전 값은 `src/version.ts` 한 곳에서만 관리합니다.
`package.json` 의 `version` 과 반드시 일치해야 하며, 불일치 시 빌드가 실패합니다
(`npm run version:check` → `prebuild` 훅에 연결됨).

**버전 올리는 절차**

```bash
# 1. src/version.ts 의 APP_VERSION 수정
# 2. package.json 의 version 수정 (같은 값)
# 3. CHANGELOG.md 에 항목 추가
npm run version:check      # 일치 확인
npm run build              # prebuild 가 자동 재검사
node scripts/verify-dom.mjs  # 32개 DOM 검증
git tag v1.1.0 && git push origin v1.1.0
gsk hosted deploy
```

**자료(보고서·엑셀) 버전 각인**: 다운로드되는 보고서 HTML과 엑셀에는 생성 시점의 버전이
찍힙니다. 엑셀 파일명은 `코스피_종목분석_YYYYMMDD_v1.0.0.xlsx` 형식입니다.
→ 나중에 "이 자료가 어느 버전에서 나온 건지" 추적할 수 있습니다.

## 2. 핵심 설계 결정 (중요)

### 왜 "실시간 조회"가 아니라 "스냅샷 + 개별 실시간"인가

검증 결과 **네이버금융 API는 종목당 재무 1회 호출에 약 820ms**가 걸립니다.
942종목 × 2회 호출 = **약 60~90초**가 필요합니다.

Cloudflare Workers는 **요청당 서브리퀘스트 50개 제한**과 CPU 타임 제한이 있어
요청 시점에 942종목을 긁는 것은 **구조적으로 불가능**합니다.

따라서 3단 구조를 채택했습니다.

```
[1] 빌드타임 스냅샷  : scripts/fetch-snapshot.mjs → src/data/snapshot.json (411KB)
                      942종목 재무+시세를 50초에 수집, 번들에 포함
[2] 서버측 필터링    : /api/stocks 가 메모리에서 즉시 필터/정렬/페이지네이션 (<10ms)
[3] 개별 실시간 갱신 : /api/stock/:code/live 가 해당 종목만 네이버 실시간 조회
```

**트레이드오프(솔직히)**: 재무지표는 스냅샷 시점 기준입니다. 주가는 종목 상세에서 실시간으로 갱신됩니다.
지표를 최신으로 유지하려면 `npm run snapshot` 후 재배포하세요.

### 데이터 정합성 검증 결과

| 항목 | 결과 |
|---|---|
| 코스피 전체 행 | 2,495행 |
| ETF / ETN | 1,553개 → **제외** |
| 실주식 | **942종목** (우선주 109개 포함) |
| 업종 매핑 | 940/942 (네이버 79개 업종 그룹) |
| 부채비율·영업이익률·PBR | 935/942 (99.3%) |
| PER | 732/942 (77.7%) |
| 배당수익률 | 681/942 (72.3%) |

**PER 누락 210건의 원인을 팩트체크했습니다:**
- 203건: 순이익 적자(EPS 음수) → **PER 계산이 원천적으로 불가능한 정상 케이스**
- 7건: 지배주주순이익 기준 EPS가 음수 (예: 하이트진로홀딩스 순이익 159억이나 EPS −109원)
- **데이터 오류는 0건** — 모두 실제로 PER을 산출할 수 없는 종목입니다.

## 3. 구현된 기능

### 3-1. 조회 조건 (요청사항)

| 조건 | 범위 | UI |
|---|---|---|
| **시가총액** | 최소/최대 (억원) | 입력 + `1,000억↑` `3,000억↑` `1조↑` `5조↑` 칩 |
| **부채비율** | 상한 (%) | 입력 + `100%↓` `200%↓` `400%↓` 칩 |
| **영업이익률** | 하한 (%) | 입력 + `흑자` `5%↑` `10%↑` `20%↑` 칩 |
| **PER** | 최소~최대 (배) | 입력 + `10배↓` `15배↓` `20배↓` 칩 |
| **매출액** | 하한 (억원) | 입력 |

### 3-2. 추가 지표 (요청: 2~3개 → 4개 구현)

| 지표 | 설명 |
|---|---|
| **ROE** | 자기자본이익률 하한 (%) |
| **PBR** | 주가순자산비율 상한 (배) |
| **배당수익률** | 하한 (%) |
| **매출 3년 CAGR** | 연평균 매출성장률 하한 (%, 자체 계산) |

### 3-2b. 분기 실적 지표 (5종)

네이버금융 `finance/quarter` API는 **최근 5개 분기**의 **단일분기(비누적)** 확정 실적을 제공합니다.

| 필터 | 설명 |
|---|---|
| **qYoYMin** | 분기 매출 YoY 하한 (%) — 전년 동기 대비 |
| **qOpYoYMin** | 분기 영업이익 YoY 하한 (%) |
| **qOpMarginMin** | 분기 영업이익률 하한 (%) |
| **qQoQMin** | 분기 매출 QoQ 하한 (%) — 직전 분기 대비 |
| **opStreakMin** | 영업이익 흑자 연속 분기수 하한 (0~5) |

**⚠ 단일분기 판정 근거 (실측)**
삼성전자 2025년 4개 분기 합계 `745,663 + 860,617 + 938,374 + 791,405(Q1) = 3,336,059억`
= 연간 매출 `3,336,059억` 과 **정확히 일치**. 누적이었다면 Q4 값 자체가 연간값이어야 하므로 단일분기 확정.
(현대차 Q3 468,386 < Q2 467,214 로 감소하는 것도 누적이 아님을 재확인)

**⚠ 분기 창 한계**
API가 5분기만 주므로 흑자연속 최대값은 5입니다. 5 = "제공된 5개 분기 전부 흑자".
분기 데이터가 없는 7종목은 리츠·인프라펀드·X클래스 수익증권으로, 구조상 분기 재무제표가 없습니다.

### 3-3. 부가 기능

- **빠른 조건 프리셋 5종**: 가치주 / 성장주 / 배당주 / 저부채 / 대형주
- **즐겨찾기**: 별 클릭 → localStorage 저장, 헤더에 개수 배지
- **즐겨찾기만 보기**: 서버측 화이트리스트 필터 (페이지와 무관하게 전체에서 조회)

- **종목 상세 드로어**: 연간 재무 3개년 + **실시간 지표** + 3개년 실적 추이 표

- **CSV 내보내기**: 현재 조건 전체(최대 5,000건) + 메모/태그 포함, BOM 처리로 엑셀 한글 정상
- **다크 아닌 라이트 테마**, 모바일 반응형 (≤720px에서 업종 컬럼 숨김)
- **키보드 접근성**: `/` 검색 포커스, ESC 닫기, 정렬 헤더 tabindex

### `GET /api/stocks`
조건 검색 (서버측 필터링)

**파라미터**

debtRatioMax      부채비율 상한 (%)
opMarginMin       영업이익률 하한 (%)
perMin / perMax   PER 구간 (배)
revenueMin        매출액 하한 (억원)

### `GET /api/stock/:code`
스냅샷 기준 단일 종목

### `GET /api/stock/:code/live`
네이버금융 실시간 조회 (2분 메모리 캐시)
→ 현재가, PER, PBR, EPS, BPS, 배당수익률, 외국인소진율, 52주 최고/최저, 3개년 재무 시계열

### `GET /api/stocks/names`
자동완성용 코스피 종목 인덱스 (`[[code, name], ...]`, 942건 약 26KB). 입력창 포커스 시 지연 로드.

### `GET /api/prices/stock/:code`
**종목 추가**용 종가 시계열. 코스피 화이트리스트에 없는 코드는 `400 not_kospi`.
→ `{ code, name, closes[928], monthly{ym:close}, annual{year:close}, period{...}, cached }`

### `GET /api/prices`
분석 요약. `summary`(파생 지표) · `monthly` · `annual` · **`period`**(기간 최고/최저) 반환.

### `GET /api/meta` · `GET /api/health`
수집 메타데이터 / 헬스체크

## 9. 알려진 제약 (솔직한 고지)

1. **재무지표는 스냅샷 시점 기준**입니다. 실시간이 아닙니다.
2. **PER/PBR/배당수익률**은 수집 시점 시세 기준이라 당일 주가 변동이 반영되지 않습니다.
   (종목 상세 드로어에서만 실시간)
3. **DART 미연동** — 요청에 "DART 또는 네이버증시"라고 하셨고, DART는 API 키 발급과
   공시 파싱이 필요하며 지표 산출이 복잡합니다. 네이버금융이 요청하신 5개 지표를
   모두 제공하므로 **네이버금융 단일 소스**로 구현했습니다.
4. **우선주는 기본 포함**입니다. "우선주 제외" 체크박스로 833종목만 볼 수 있습니다.
5. **투자 판단의 근거로 단독 사용하지 마세요.** 정보 제공용입니다.

## 11. 코스피 전용 정책 (확정)

**코스닥·코넥스는 수집·표시 대상에서 제외합니다.** 이는 우연이 아니라 코드로 강제됩니다.

### 3중 방어

| 계층 | 방어 수단 | 동작 |
|---|---|---|
| **수집기** | `sosok !== '0'` 검증 | 코스피(`sosok=0`)가 아닌 종목이 1건이라도 섞이면 **수집 즉시 중단** (`process.exit(1)`) |
| **스냅샷** | `market: 'KOSPI'` 필드 | 942건 전부 `KOSPI`로 명시 기록 |
| **런타임** | `KOSPI_STOCKS` 필터 | 스냅샷이 오염·수동편집 되어도 `market !== 'KOSPI'`는 API 응답에서 제외 |

### 검증 근거 (실측)

```
소스 엔드포인트      : /api/stocks/marketValue/KOSPI  (코스닥 엔드포인트 호출 안 함)
수집 942종목 sosok   : { "0": 942 }        ← 코스피 단일
수집 942종목 거래소  : { "KS": 942 }       ← 코스피 단일
코스닥 1,800종목 교집합 : 0 건
```

`9`로 시작하는 2종목(프레스티지바이오파마·엘브이엠씨홀딩스)은 코드만 보면 코넥스처럼
보이지만, 실제 응답은 둘 다 `sosok=0` / `exchange=KS` 로 **코스피 상장 종목**입니다.
따라서 제외하지 않는 것이 맞습니다.

### 변경 금지 사항

- 수집기에서 `KOSPI` → `KOSDAQ`으로 바꾸거나 두 마켓을 합치지 마세요.
- `sosok` 검증 블록을 제거하지 마세요. 코스닥이 섞이면 요구사항 위반입니다.
- UI의 `코스피 전용` 배지를 제거하지 마세요. 사용자가 마켓 범위를 즉시 알 수 있어야 합니다.
